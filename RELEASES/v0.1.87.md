# v0.1.87 — Doctor warning handling and stable client paths

**Type:** Distribution release carrying bundle **0.1.83**.

## Fixed

- **Doctor warning handling:** `datacore update` and the installer no longer stop with
  "Install stopped" when the bundle's doctor report has a warnings field (bundle 0.1.82 and later).
  Warnings are shown and do not block. Client registration (Claude Code, Claude Desktop) and the
  login agent now run again after an upgrade. Older doctor report formats are still accepted.

## Changed

- **Stable client paths (from bundle 0.1.83):** The Claude Desktop entry, the macOS login agent
  and Datacore launch commands in the Codex config point at the stable `~/.datacore/current` path
  instead of a versioned bundle directory, so they keep working across updates and after old
  versions are removed. Client config is written only after a successful install.

## Known limits

- Workers still receive the bridge's own Runtime credential, so on this edition a worker
  can act in Runtime with the bridge's identity. A later release will give each worker
  only its own credential.
- A worker's MCP helper process reloads the bundle `.env`, so the scrub covers only the
  worker's own environment. Also note that a worker can read the bundle `.env` from disk.
- An upgrade can reset the enabled worker list to the default profile; run `datacore worker list`
  afterwards and re-add your choices with `datacore worker add`.

## Upgrading

Run `datacore update`:

```sh
datacore update
```

If you are on v0.1.86 and an update stopped with "Install stopped", run `datacore update` again;
your data was not affected. After the update, restart Claude Desktop so it picks up the stable path.
