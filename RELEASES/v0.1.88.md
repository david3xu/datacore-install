# v0.1.88 — Lockstep versioning, upgrade project summary and CLI guards

**Type:** Distribution release carrying bundle **0.1.88**.

## Versioning

- **Lockstep version alignment:** The installer version and Local Edition bundle version are now aligned in lockstep. This release and its runtime bundle are both 0.1.88; bundle versions 0.1.84–0.1.87 were skipped on purpose to bring the version streams together. From now on, installer vX.Y.Z always ships bundle X.Y.Z.

## Fixed

### Installer

- **Upgrade project summary:** On upgrade, the final installer summary now inspects the workspace mapping and reports mapped projects correctly (`mapped (see: datacore project list)`) instead of "not configured", and omits the unnecessary `datacore project link` next step.
- **CLI backup and restore help guards:** `datacore backup --help` and `datacore restore --help` (and `-h`) now print usage locally and exit without executing the bundle script, preventing accidental backup creation or service stoppage.
- **Installer header URL:** Updated the header usage comment in `install.sh` to use the version-free repository URL.

### Bundle 0.1.88

- **Compose environment precedence:** Compose uses bundle `.env` values over ambient shell environment variables; a shell-exported `DATACORE_HTTP_PORT` no longer breaks service startup.
- **Backup script help and restart:** `backup --help` no longer runs a backup, and `datacore backup` restarts the services it stopped once archiving finishes.
- **Restore script help:** `restore --help` prints usage instead of running a restore.

## Known limits

- Workers still receive the bridge's own Runtime credential, so on this edition a worker
  can act in Runtime with the bridge's identity. A later release will give each worker
  only its own credential.
- A worker's MCP helper process reloads the bundle `.env`, so the scrub covers only the
  worker's own environment. Also note that a worker can read the bundle `.env` from disk.
- An update can reset the worker list, and earlier choices are restored; check `datacore worker list`.

## Upgrading

Run `datacore update`:

```sh
datacore update
```
