# v0.1.86 — Stable Claude identities, bridge isolation and restart verification

**Type:** Distribution release carrying bundle **0.1.82**.

## Changed

- **Claude identities:** New installs use `claude-code`, `claude-desktop` and
  `claude-code-lifecycle-operator`. An upgrade migrates the dated IDs and prints a notice. From
  the bundle directory, the operator then runs `./connect-claude-code.sh` and
  `./write-claude-desktop-config.sh`, restarts both clients, and revokes each superseded ID with
  the printed command.

- **Host worker bridge loopback binding:** The host worker bridge listens on `127.0.0.1` by
  default, and doctor warns on a non-loopback, unset or empty bind.

- **Dispatched worker isolation:** Dispatched workers no longer inherit bridge-internal settings
  or secret-bearing variables. This reduces what reaches a worker through its environment; it is
  not a security boundary, because workers run as the operator's OS user.

- **Git worktree and bare repository handling:** `project list` and `project link` recognise
  linked git worktrees as repositories; a bare repository is not treated as a working repository,
  so link warns but still maps it, and list labels it "(not a git repository)".

- **Bridge restart verification:** `project link` and `project unlink` verify a real bridge
  restart. When the restart cannot be verified, the command exits 1 with remediation; with no bridge
  running, it does nothing.

## Known limits

- Workers still receive the bridge's own Runtime credential, so on this edition a worker
  can act in Runtime with the bridge's identity. A later release will give each worker
  only its own credential.
- A worker's MCP helper process reloads the bundle `.env`, so the scrub covers only the
  worker's own environment. Also note that a worker can read the bundle `.env` from disk.

## Upgrading

Run `datacore update`:

```sh
datacore update
```

Then complete the identity follow-up steps:

1. From the bundle directory, run `./connect-claude-code.sh` and `./write-claude-desktop-config.sh`.
2. Restart both clients.
3. Revoke each superseded ID with the printed command. Revocation is not automatic: an old token
   stays valid until it is revoked.

If no ID was superseded (a fresh install, or an upgrade that already had canonical IDs), nothing is
printed and there is nothing to revoke.
