# v0.1.86 — Stable Claude identities, bridge isolation and restart verification

**Type:** Distribution release carrying bundle **0.1.82**.

## Changed

- **Claude identities:** New installs use `claude-code`, `claude-desktop` and
  `claude-code-lifecycle-operator`. An upgrade migrates the dated IDs and prints a notice. The
  operator then runs `./connect-claude-code.sh` and `./write-claude-desktop-config.sh`, restarts
  both clients, and revokes each superseded ID with the printed command.

- **Host worker bridge loopback binding:** The host worker bridge listens on `127.0.0.1` by
  default, and doctor warns on a non-loopback, unset or empty bind.

- **Dispatched worker isolation:** Dispatched workers no longer inherit bridge-internal settings
  or secret-bearing variables. This prevents accidental collisions and leaks; it is not a security
  boundary, because workers run as the operator's OS user.

- **Git worktree and bare repository handling:** `project list` and `project link` recognise
  linked worktrees and reject bare repositories.

- **Bridge restart verification:** `project link` verifies a real bridge restart.

## Known limits

- Workers still receive the bridge's own Runtime credential (follow-up D10).
